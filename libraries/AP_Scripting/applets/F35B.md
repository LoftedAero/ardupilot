# F-35B Custom Flight Logic

A single, modular applet holding custom flight logic for an F-35B style tiltrotor
VTOL. Each subsystem is independently enabled and keeps its own parameter prefix.
The script is intentionally the **sole authority** for flight-mode changes so that
subsystems reacting to (or commanding) the mode never race each other.

Current subsystems:

- **Doors** — drives a PWM output for the motor-cover doors and gates entry into
  VTOL (Q) modes until the doors have physically opened.

Install: set `SCR_ENABLE = 1`, copy `F35B.lua` to the `APM/scripts` directory on the
SD card, and reboot.

---

## Doors subsystem

The doors cover the lift motors and tilt mechanisms. An external board reads a single
PWM signal and drives the doors: closed (~1000µs) for fixed-wing, partially open
(~1500µs) for transition, fully open (~2000µs) for hover.

Because the doors physically block the lift motors and tilts, VTOL flight must not
begin until the doors have opened. A Lua script cannot veto a pilot's normal flight-mode
switch (the RC handler applies it directly), so instead **the script owns all mode
changes**: the physical 6-position mode selector is rerouted to a plain RC channel that
the script reads, and the autopilot's own flight-mode switch is repurposed as an
emergency override. When a VTOL position is selected the script opens the doors, waits
`DOOR_ENTRY_MS` (until the doors reach operating clearance), and only then commands the VTOL
mode. While it waits, the aircraft stays in fixed-wing, so the lift motors never spool and
the tilts never move against a shut door — there is no race.

### Door position by flight phase

| State | Door PWM |
|-------|----------|
| Pure fixed-wing (transition complete, lift motors stowed) | `DOOR_CLOSED` (~1000) |
| VTOL system in play, high airspeed | `DOOR_PART` (~1500) |
| VTOL system in play, low airspeed | `DOOR_OPEN` (~2000) |

"VTOL system in play" means in a VTOL mode, transitioning either direction
(`in_assisted_flight`), or a pending inbound VTOL entry. In those states the partial/full
door position is driven by **airspeed** (sensed or synthetic), and the crossover airspeed is
**chosen by transition direction** — so the two directions can use different speeds:

- **Outbound (VTOL→FW):** full below `DOOR_PART_AS`, partial at/above it. Doors start full in
  hover, neck to partial partway up as the aircraft accelerates past `DOOR_PART_AS`, then close
  **once the nacelles are fully forward AND any dedicated lift motor has spooled down** — the
  script watches the tilt output (`DOOR_TILT_FN` ≥ `DOOR_TILT_FWD`) and the lift-motor output
  (`DOOR_LIFT_FN` ≤ `DOOR_LIFT_OFF`) directly, so it waits out the intermediate airspeed-wait
  angle and never closes on moving nacelles or a still-spinning lift motor.
- **Inbound / in-VTOL (FW→VTOL, hover)** — in a VTOL mode: full below `DOOR_FULL_AS`, partial
  above, but **only until the doors first reach full** in that VTOL session — after that they
  stay full for the rest of the session (reset on leaving VTOL). On entry the doors open to
  their operating position (partial when fast); after `DOOR_ENTRY_MS` the VTOL mode is entered
  and it decelerates the aircraft; as airspeed drops through `DOOR_FULL_AS` the doors open fully
  and stay full — so deliberately flying fast again in VTOL won't neck them and cost authority.
  The script never waits for the aircraft to slow *before* entering VTOL, because nothing
  decelerates it while held in fixed-wing.

Because the threshold is selected by direction, `DOOR_FULL_AS` (inbound "go full" speed) is
typically **higher** than `DOOR_PART_AS` (outbound "go partial" speed) — there is no ordering
requirement and no unstable overlap. A change must also persist ~0.75 s before taking effect,
which rejects airspeed noise near a threshold.

If no airspeed estimate is available, the doors stay fully open whenever the VTOL system is
in play (safe for VTOL, no drag reduction).

### Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `DOOR_ENABLE` | 0 | 0 = disabled, 1 = enabled |
| `DOOR_MODE_CH` | 0 | RC input channel carrying the rerouted 6-position mode selector. **Must not equal `FLTMODE_CH`.** 0 disables mode gating (doors still track phase). |
| `DOOR_MODE1` | 0 (MANUAL) | Target mode number for selector position 1 |
| `DOOR_MODE2` | 5 (FBWA) | Target mode number for selector position 2 |
| `DOOR_MODE3` | 7 (CRUISE) | Target mode number for selector position 3 |
| `DOOR_MODE4` | 19 (QLOITER) | Target mode number for selector position 4 |
| `DOOR_MODE5` | 18 (QHOVER) | Target mode number for selector position 5 |
| `DOOR_MODE6` | 21 (QRTL) | Target mode number for selector position 6 |
| `DOOR_FUNC` | 94 | `SERVOx_FUNCTION` assigned to the door output (94–109 = Scripting1–16) |
| `DOOR_CLOSED` | 1000 | PWM for closed (fixed-wing) |
| `DOOR_PART` | 1500 | PWM for partially open (fast / transition, reduced drag) |
| `DOOR_OPEN` | 2000 | PWM for fully open (low speed / hover) |
| `DOOR_ENTRY_MS` | 3000 | Time (ms) from commanding the doors open to a safe VTOL entry — i.e. how long the doors take to reach the partial (operating clearance) position. Inbound VTOL entry is withheld this long. |
| `DOOR_PART_AS` | 6 | **Outbound** (VTOL→FW transition) airspeed (m/s): neck to partial at/above this while transitioning to fixed-wing. Roughly half the transition-complete airspeed. **Tune to your airframe.** |
| `DOOR_FULL_AS` | 10 | **Inbound / in-VTOL** airspeed (m/s): open fully below this while in a VTOL mode. Raise it to open fully *sooner* (at higher speed) as you decelerate into VTOL. Independent of `DOOR_PART_AS` (usually higher). |
| `DOOR_TILT_FN` | 41 | `SERVOx_FUNCTION` of the nacelle-tilt output to watch (41 = motor tilt; 75/76 = vectored left/right). The script reads this output's **PWM** (1000–2000) to know when the nacelles are stowed forward. **0 = no reading** (doors never close). |
| `DOOR_TILT_FWD` | 1900 | Tilt-output **PWM** marking nacelles fully forward (doors may close). Direction auto-detected: ≥1500 → forward is the high-PWM end (`TILT_POS ≥ this`); <1500 → forward is the low-PWM end (`TILT_POS ≤ this`). Set from the `TILT_POS` value at full forward. |
| `DOOR_LIFT_FN` | 0 | `SERVOx_FUNCTION` of a dedicated (non-tilting) lift motor to watch, so the doors don't close while it is still powered / spooling down. Motor N function = 32+N (motors 1–8) or 73+N (motors 9–12), e.g. motor 1 = 33. **0 disables** (pure tiltrotor). |
| `DOOR_LIFT_OFF` | 1050 | Output PWM at/below which the watched lift motor counts as off. Set from `LIFT_PWM` telemetry, between the motor-stopped value and its idle/running value. |
| `DOOR_NOZ_MS` | 3500 | Time (ms) the physical nozzle takes to travel the tilt output's full PWM range (`SERVOx_MIN` to `SERVOx_MAX` of the `DOOR_TILT_FN` output). The script estimates where the nozzle actually is and closes only once that estimate reads forward. The estimate follows a deploy at once and a stow at this rate, so it never reads forward before a nozzle that stows this fast, however fast the nozzle deploys. A normal 30°/s slew (the full range in about 3 s) adds little or no wait; the faster tilt in MANUAL and at the end of an outbound transition (at least 90°/s) does. Measure it and add margin. 0 = trust the output. |
| `DOOR_DEBUG` | 0 | `1` = verbose GCS messages on every door state change and mode/latch action (for SITL testing). Leave `0` for flight. |

Selector position is banded from the channel PWM using ArduPilot's standard 6-position
thresholds (≤1230, 1231–1360, 1361–1490, 1491–1620, 1621–1749, ≥1750). Mode numbers are
the ArduPlane values (see https://mavlink.io/en/messages/ardupilotmega.html#PLANE_MODE).

### How to set up

1. `SCR_ENABLE = 1`, copy `F35B.lua` to `APM/scripts`, reboot, then `DOOR_ENABLE = 1`.
2. Assign a servo output for the door board: set one `SERVOx_FUNCTION = 94` (Scripting1)
   and set `DOOR_FUNC = 94`. **Set that output's `SERVOx_TRIM` to the partial position**
   (`DOOR_PART`, the sequencer's MID). The script's door command lapses 0.5 s after the script
   stops refreshing it, and the output then returns to its trim. With the trim at MID, a script
   that stops, errors out in fixed-wing flight, or is disabled with `DOOR_ENABLE 0` leaves the
   lift fan door at its intermediate position and every other door open: clear for a later VTOL
   entry, without opening the lift fan door fully at cruise speed. Before the script first runs
   after boot the output sends no pulses at all, whatever the trim; the sequencer holds the
   nozzle doors open until it sees a valid signal.
3. On the transmitter, route the 6-position mode selector to a **plain RC channel** and
   set `DOOR_MODE_CH` to it.
4. **Ensure `FLTMODE_CH` does NOT point at `DOOR_MODE_CH`.** Point `FLTMODE_CH` at a
   separate 2-position switch and use it as a script-independent emergency override:
   set its `FLTMODE` entries to safe fixed-wing modes (e.g. FBWA and MANUAL). Switching
   to MANUAL is always safe — it never starts a blocked VTOL — so this override works
   even if the script has stopped.
5. Set `DOOR_MODE1..6` to the modes you want on each selector position, set `DOOR_ENTRY_MS`
   to the time your doors take to reach operating (partial) clearance (add margin), and tune
   `DOOR_PART_AS` / `DOOR_FULL_AS` to your outbound/inbound crossover airspeeds.
6. Measure how long the nozzle takes to cross the tilt output's full range when the output
   moves faster than the nozzle can follow (switch to MANUAL from a hover, on the bench), and
   set `DOOR_NOZ_MS` to that plus margin. Only the stow speed matters: the estimate follows a
   deploy at once. Check the estimate against the real nozzle with the `NOZ_EST` telemetry.

Updating from a version without `DOOR_NOZ_MS` needs a reboot: the `DOOR_` parameter table
grows by one, which a scripting restart alone can't do.

### Telemetry (Mission Planner)

Published as `NAMED_VALUE_FLOAT` at ~5 Hz (visible under **Data → Status**, pinnable to
the **Quick** tab / HUD):

- `DOOR_PWM` — commanded door PWM.
- `DOOR_ST` — state: 0 = closed, 1 = partial, 2 = open, 3 = opening (entry delay running).
- `VTOL_DLY` — seconds remaining in the `DOOR_ENTRY_MS` delay before VTOL engages.
- `TILT_POS` — the watched nacelle-tilt output **PWM** (1000–2000). Use it to set
  `DOOR_TILT_FWD` and to confirm `DOOR_TILT_FN` is the right function (it should sweep as the
  nacelles move; if it's stuck, the function is wrong — test armed/in-flight, not disarmed).
- `LIFT_PWM` — the watched dedicated lift-motor output PWM (0 if `DOOR_LIFT_FN=0`). Use it to
  set `DOOR_LIFT_OFF` and to confirm `DOOR_LIFT_FN` is the right motor.
- `NOZ_EST` — the estimated physical nozzle position, in tilt-output PWM (0 if no tilt
  reading). The doors close only once this reads forward. It jumps with the output on a
  deploy and lags it on a stow. Compare it with the real nozzle on a stow to check
  `DOOR_NOZ_MS`.
- `DOOR_AS` — the airspeed estimate (m/s) the door thresholds use (-1 if none). This is the
  AHRS estimate, which can differ from the HUD airspeed when an airspeed sensor is fitted but
  not used (`ARSPD_USE 0`).

These are `NAMED_VALUE_FLOAT` messages. They go out on the MAVLink link, but some GCS versions
(incl. some Mission Planner builds) don't surface them in the Status list — check the MAVLink
Inspector to confirm they're arriving. If your GCS won't show them, set `DOOR_DEBUG = 1`: a
text **heartbeat** (`F35B hb st=… t=… l=… as=…`, where `t` = tilt PWM, `l` = lift PWM) then
prints to the Messages window every ~2 s. All debug lines are kept ≤50 chars so the GCS
doesn't wrap them.

Only discrete **events** are sent to the GCS HUD (`F35B: doors opening ...`, `doors open -
entering VTOL`, `doors closed`). The routine partial↔full position changes are intentionally
**not** printed — watch `DOOR_ST` (or the heartbeat) for those.

### Behavior reference

Door position is evaluated every ~50 ms in priority order:

1. **Inbound entry pending** (a VTOL mode selected from fixed-wing) → doors driven open toward
   the operating position; the mode stays fixed-wing until `DOOR_ENTRY_MS` elapses, then VTOL
   engages.
2. **VTOL geometry/propulsion active** → doors open (airspeed picks partial vs full). "Active"
   = **any** of: in a VTOL mode; nacelles not yet at the forward end (`DOOR_TILT_FWD`, direction auto-detected);
   dedicated lift motor still powered (`LIFT_PWM > DOOR_LIFT_OFF`); or armed **and**
   `in_assisted_flight` (a conservative extra).
3. **Otherwise** → closed, once the estimated nozzle position has also reached forward (until
   then, open as in 2).

**Partial vs full** (within "open"): threshold is `DOOR_FULL_AS` in a VTOL mode, else
`DOOR_PART_AS`; partial at/above, full below; a change must persist ~0.75 s (anti-chatter);
no airspeed estimate → full. Once the doors have opened fully in a VTOL session they stay
full for the rest of it (reset on leaving VTOL), so partial only appears during the initial
fast inbound entry — deliberately flying fast in a VTOL mode never necks the doors.

**Mode changes** are edge-triggered on the selector: it acts only when the position *changes*;
it is ignored while in externally-set MANUAL or while RC input is not valid; fixed-wing targets
apply instantly; a VTOL target applies instantly if already in VTOL, otherwise it gates through
the open-doors delay. Any mode change during that delay (override, failsafe, GCS) cancels the
pending entry.

Closing requires **three things at once** — fixed-wing, nacelles forward, and lift motor off —
and the estimated nozzle position must have caught up with the tilt output. These are output
commands and an estimate, not measured positions. Opening errs toward "any reason."

| # | Scenario | Door motion | Logic |
|---|----------|-------------|-------|
| 1 | Disarmed, fixed-wing, nacelles forward, lift off | Closed | no "active" condition |
| 2 | Disarmed in a VTOL mode (pre-arm) | Open | `in_vtol` |
| 3 | Disarmed with `DISARMED_TILT_UP` (nacelles up) | Open | nacelles not forward |
| 4 | Inbound: select VTOL from fixed-wing | Open→partial; hold FW `DOOR_ENTRY_MS`, then enter VTOL | pending-entry gate |
| 5 | In VTOL hover (slow) | Full | `in_vtol`, airspeed < `DOOR_FULL_AS` |
| 6 | Fast flight *within* a VTOL mode | Full (partial only during the initial fast inbound entry, then latched full for the session) | `in_vtol` + session latch |
| 7 | VTOL→VTOL selector change | Stays open, instant switch, no delay | already `in_vtol` |
| 8 | Outbound: select fixed-wing from VTOL | Full→partial as speed builds; close once nacelles forward AND lift off | tilt + lift watch |
| 9 | Steady fixed-wing cruise | Closed | nacelles forward, lift off |
| 10 | Q_ASSIST fires in fixed-wing (if enabled) | Open reactively | nacelles back / lift powered / `assisted` |
| 11 | GCS commands a VTOL mode directly | Open reactively + warning | can't withhold |
| 12 | GCS/failsafe sets fixed-wing while selector on VTOL | Respected; doors follow transition | edge-trigger |
| 13 | RTL / AUTO auto-transition to VTOL | Open reactively + warning (limitation) | can't pre-gate |
| 14 | Override → MANUAL (from VTOL or FW) | Immediate MANUAL; doors stay open until nacelles forward + lift off and the nozzle estimate is home (MANUAL tilts faster than the nozzle), then close; selector locked out | MANUAL lockout + tilt/lift watch + nozzle estimate |
| 15 | Selector moved during a pending entry | Pending cancels or retargets | edge-trigger resets pending |
| 16 | No airspeed estimate | Open region → full | airspeed fallback |
| 17 | `DOOR_TILT_FN`/`DOOR_LIFT_FN` mis-set | Stays open (fail-safe) | reads as "active" |
| 18 | RC loss, or before the receiver connects | No selector action; follows failsafe mode | `rc:has_valid_input()` false |
| 19 | Script stopped, or `DOOR_ENABLE 0` | Door command lapses after 0.5 s; output returns to `SERVOx_TRIM` (set it to MID); MANUAL override still works | timed output |
| 20 | Mode changed (override / failsafe / GCS) during a pending entry | Entry cancelled + warning; doors follow the new mode | pending cancels on mode change |
| 21 | Script runtime error | Error reported, loop retried every 1 s; doors held open if VTOL is in play, otherwise the command lapses to the trim (MID) | protected wrapper + timed output |
| 22 | Outputs read stowed, nozzle still catching up | Doors stay open until the nozzle estimate reaches forward | nozzle estimate |
| 23 | Script starts on the ground | Nozzle position unknown: assumed fully deployed, so the doors wait a full `DOOR_NOZ_MS` before closing | nozzle estimate |
| 24 | Script restarts in flight (armed) | Nozzle assumed where the output says; doors stay closed in cruise | nozzle estimate |

### Notes and limitations

- The open-doors-first **delay** is fully race-free only for mode changes the script owns
  (the rerouted selector and its own `set_mode`). VTOL entered by GCS command, failsafe
  (QRTL/QLAND), or an AUTO mission leg cannot be withheld by the script; for those the
  doors open immediately and a warning is sent, but door travel may briefly lag motor
  spin-up. Keep `DOOR_ENTRY_MS` modest and give AUTO VTOL legs lead time.
- **RTL auto-transition risk (unresolved — revisit before real flight):** RTL (and AUTO
  VTOL landings) auto-transition to VTOL, which the script only detects once the transition
  is already underway. The doors therefore open *reactively* — the tilt/lift motors begin
  moving before the doors are fully open. This is invisible in SITL but on real hardware the
  motors could load against not-yet-open doors. Accepted for SITL testing only. Before real
  flight, mitigate (e.g. pre-open the doors whenever armed in RTL/AUTO, or add a firmware
  motor-spool gate) or avoid auto-transitioning RTL with the doors closed.
- Selecting a different VTOL position while already hovering switches immediately (doors
  are already open) with no delay.
- The script acts only when the selector position **changes**, so an emergency override
  or failsafe that sets a fixed-wing mode is respected — the script will not re-command
  the VTOL selection until you move the selector.
- **MANUAL is a hard lockout.** While the vehicle is in `MANUAL` set from outside the script
  (i.e. the `FLTMODE_CH` emergency override, GCS, or a failsafe — anything but the script's
  own `set_mode`), moving the selector does **nothing** except print `MANUAL override active
  - selector ignored`. To hand control back to the script, leave MANUAL (override switch back
  to its rest position) and then move the selector to the mode you want. This stops the
  selector from yanking you out of an emergency-manual bailout. It also covers a pending
  entry: any mode change during the `DOOR_ENTRY_MS` wait cancels it (`mode changed, VTOL
  entry cancelled`), and you re-select to try again.
- **Disarmed on the ground:** the doors follow the nacelle position — closed when the nacelles
  are forward (default disarmed state), open when they are up (VTOL mode, or the
  `Q_OPTIONS DISARMED_TILT_UP` behaviour). So switching VTOL→fixed-wing on the ground closes
  the doors once the nacelles settle forward.
- **Close timing watches the nacelle tilt output** (`DOOR_TILT_FN`) and, if set, a dedicated
  lift motor's output (`DOOR_LIFT_FN`) — not `in_assisted_flight` — so it is correct regardless
  of `Q_ASSIST` and handles the intermediate airspeed-wait tilt angle and the lift-motor
  spool-down. It detects the forward direction from `DOOR_TILT_FWD`; tune `DOOR_TILT_FWD` / `DOOR_LIFT_OFF`
  from the `TILT_POS` / `LIFT_PWM` telemetry. If a watched function is wrong/unassigned the
  doors stay open (fail-safe) — you'll see `TILT_POS` near 0 or `LIFT_PWM` at 0.
- **Dedicated lift motors:** with `DOOR_LIFT_FN` set, the doors won't close until that motor's
  output has fallen to `DOOR_LIFT_OFF` (spooled down), covering the case where the nacelles
  reach forward while a non-tilting lift motor is still powered or windmilling down. If you
  have several lift motors that spool together, watch the one that is slowest to stop.
- **`Q_ASSIST` interaction:** with the tilt-watch close, the door logic no longer depends on
  `Q_ASSIST` — enabling/disabling it is a flight-dynamics choice. If `Q_ASSIST` is enabled the
  doors still open reactively whenever assist deploys the nacelles in fixed-wing flight (the
  nacelles tilt back, which the script sees). If you rely on `Q_ASSIST`, that is one more
  external VTOL activation the script opens for reactively rather than pre-gating.
- **Inbound entry happens at partial door clearance.** VTOL is entered after `DOOR_ENTRY_MS`
  (doors at the partial operating position), while the aircraft may still be fast — the VTOL
  mode then decelerates it and the doors open fully once airspeed drops through `DOOR_FULL_AS`.
  This assumes the partial position gives enough clearance to start the lift motors/tilt
  safely; size `DOOR_PART` accordingly.
